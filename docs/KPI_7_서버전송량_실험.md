# KPI ⑦ 서버 전송량 — 실험 방법과 결과 (C 파트 · 전지혜)

> 한 줄 결과 : **30분 운행 기준 사진 1,800장(81.4MB) → 180장(8.1MB), 약 73MB · 90% 줄임**
> 실험 환경 : 연습 서버(mock_server) + 갤럭시 폰 1대 (기사 앱 c-app 브랜치)

---

## 1. 무엇을 쟀나

졸음을 잡으려고 운행 중 사진을 서버로 보낼 때, **얼마나 많은 데이터를 보내는지**를 쟀어요.

| 비교 | 보내는 방식 |
|---|---|
| 줄이기 전 (기준) | 카메라 사진을 **1초에 1장씩 계속** 서버로 보냄 |
| 줄인 뒤 (우리 앱) | 폰 안 AI(ML Kit)가 먼저 눈 · 고개를 보고, **졸음이 의심되는 순간에만** 사진 1장을 보냄 |

## 2. 앱이 사진을 보내는 조건 (줄인 방법)

폰 안에서 1차 판정을 하고, 아래 조건에 걸릴 때만 서버 `/detect` 로 사진을 보내요.
(코드 : `sleep_detector_app/lib/services/eye_monitor.dart`, `lib/screens/drive_screen.dart`)

- 눈을 **1.5초 이상 계속 감음** → 미세수면 의심
- 최근 30초 동안 눈 감은 비율(PERCLOS)이 **15% 이상** → 피로 누적 의심 (직전 의심 뒤 30초 안에는 다시 안 보냄)
- 고개를 **3초 이상 숙임** → 미세수면 의심
- **앞 사진을 아직 처리 중이면 다음 사진은 건너뜀** (`_sending` — 같은 졸음을 두 번 보내지 않음)
- 경고 뒤 눈을 뜬 첫 순간부터 **10초는 다시 안 보냄** (눈 비비기로 단계가 바로 오르는 것 막기)
- 그 밖의 시간에는 사진 없이 **30초마다 상태 확인(ping)** 만 보냄

## 3. 실험 방법

### ① 장수 (몇 장을 보내나)
- **기준 1,800장** : 1초에 1장 × 30분(1,800초) = 1,800장
- **우리 앱 180장** : 1시간 시험 운행에서 서버로 간 사진 약 360장 → 30분으로 바꾸면 180장
  - 출처 : 팀 1시간 시험 기록 (노션 KPI 정리)
- → 장수 기준 **1,800 → 180장, 90% 감소** (의심 순간 10%만 보냄)

### ② 용량 (사진 1장이 몇 KB인가)
- 연습 서버에 실제로 올라온 경고 사진 파일 크기를 재서 평균을 냈어요.
  - 사진 저장 위치 : `sleep_detector_api/uploads/events/`
  - 사진 규격 : **480 × 720 JPG (세로 사진)** (앱이 카메라 화면을 JPG로 바꿔 보냄)
- 11/23 측정 : 사진 **92장**, 평균 **46.3KB** (최대 75KB)
- 계산
  - 줄이기 전 : 1,800장 × 46.3KB ≈ **81.4MB**
  - 줄인 뒤 : 180장 × 46.3KB ≈ **8.1MB**
  - 차이 : **약 73MB 줄임 (90%)**

### ③ 다시 재 보기 (11/25 확인)
- 같은 폴더의 사진이 **158장**으로 늘어난 뒤 다시 재 보니 평균 **41.0KB** (가장 작은 것 18.9KB · 가장 큰 것 75.0KB · 모두 480 × 720)
- 이 값으로 계산하면 1,800장 ≈ 72.1MB → 180장 ≈ 7.2MB
- **사진 1장 크기는 조금 달라져도, 장수를 90% 줄였기 때문에 용량도 똑같이 90% 줄어요.**

재는 방법 (같이 올린 `docs/kpi7_measure.py`) :

```
cd sleep_detector
sleep_detector_api/venv/Scripts/python.exe docs/kpi7_measure.py
```

## 4. 결과

| 항목 | 줄이기 전 (1초 1장) | 우리 앱 (의심 순간만) | 줄어든 양 |
|---|---|---|---|
| 30분 사진 장수 | 1,800장 | 180장 | 1,620장 (90%) |
| 30분 전송 용량 | 81.4MB | 8.1MB | 약 73MB (90%) |

- 목표 **90% 절감 달성**
- 사진 말고는 30초마다 가벼운 상태 확인(ping, 사진 없음)만 보내요.

## 5. 한계 (그대로 적음)

- **연습 서버(mock)에서 잰 값이에요.** 메인 서버 · 실제 차 안에서는 아직 재지 않았어요.
  - 다만 **사진을 보낼지 말지(눈 감김 · PERCLOS · 고개 숙임 조건)와 사진 크기(480 × 720 JPG)는 폰 안에서 앱이 정해요.** 그래서 받는 서버가 mock이든 main이든 보내는 장수 · 용량은 거의 같아요.
  - main에서 달라질 수 있는 건 서버 답에 따른 작은 차이뿐이에요. 예 : 경고 · 퀴즈 화면 중에는 안 보냄, 서버가 취소하면 사진 없이 한 번 더 보냄. 90% 감소라는 결론이 바뀔 정도는 아니에요.
  - 반대로 **KPI ② 경고 지연 시간은 네트워크와 서버 AI 판정 속도가 숫자에 그대로 들어가므로 main 서버에서 재야 해요.**
- 180장은 팀 1시간 시험 기록을 30분으로 나눈 값이라, **운전자 · 졸음 정도에 따라 장수가 달라질 수 있어요.** 많이 조는 운전자는 더 많이 보내요.
- 1,800장은 실제로 보낸 것이 아니라 **1초에 1장 방식이라면** 이만큼이라는 계산값이에요.
- 사진 평균 크기는 잰 시점에 따라 46.3KB(92장) / 41.0KB(158장)로 조금 달라요. 발표 숫자는 처음 잰 46.3KB 기준이에요.
